# Research: macOS Distribution (005)

All decisions below resolve the plan's open technical questions. Tool availability was checked on the maintainer's Mac (2026-10-14): `hdiutil`, `iconutil`, `codesign`, `security`, `xcrun notarytool`, `xcrun stapler`, `gh`, `uv`/`uvx`, `/usr/bin/ruby` are present; `create-dmg`, `bats` and `shellcheck` are not.

## R1. Language for the release tooling

- **Decision**: POSIX-leaning Bash scripts under `scripts/release/`, called from new Makefile targets. A shared `lib.sh` holds pure functions (version computation, tier selection, cask rendering, release-notes rendering) that tests source directly.
- **Rationale**: Every step is a call to an Apple or GitHub command-line tool; Bash keeps them visible and is what a later CI job runs anyway. The repo already has Bash helpers in `scripts/`.
- **Alternatives considered**: A Swift command-line target (heavier, needs the SDK workaround, no gain for gluing CLIs); Python (adds an interpreter dependency for every step; only the DMG layout needs Python, see R4).

## R2. Testing the scripts

- **Decision**: A small self-contained Bash test runner `scripts/release/tests/run.sh` with assertion helpers, one file per area (`test_version.sh`, `test_signing.sh`, `test_cask.sh`, `test_notes.sh`, `test_preflight.sh`). External commands (`security`, `git`, `gh`, `xcrun`) are replaced by stub executables placed first on `PATH`, or by real temporary git repositories for version tests. `make test-release` runs it; `make test` stays the Swift suite. Cask output is additionally checked with `ruby -c`.
- **Rationale**: No bats or shellcheck on the machine and no third-party test dependency is wanted; plain Bash assertions cover the pure functions, and stubs make the preflight and tier logic deterministic.
- **Alternatives considered**: bats-core via Homebrew (extra dependency for contributors); testing only by running real releases (not repeatable, publishes artifacts).

## R3. Signing identity selection and designated requirement

- **Decision**: `security find-identity -p codesigning` (without `-v`, so an untrusted self-signed certificate is still found) is parsed for, in order: an identity whose name starts with `Developer ID Application:`; an identity whose name equals `$SIGN_IDENTITY_NAME` (default `AgentMeter Signing`); otherwise ad-hoc (`-`). `SIGN_IDENTITY` set explicitly (including `-`) bypasses selection (FR-004). The identity is passed to `codesign` by its SHA-1 hash to avoid ambiguity when two certificates share a name.
- **Designated requirement**: `codesign` generates a certificate-based requirement automatically for any real certificate (`identifier "dev.rhuss.agentmeter" and certificate root = H"..."` or `certificate leaf = H"..."` for self-signed, both accepted; `anchor apple generic and certificate leaf[subject.OU] = TEAMID` style for Developer ID). Ad-hoc yields a `cdhash` requirement. The build verifies with `codesign -d -r-` and fails if a non-ad-hoc build shows `cdhash` (FR-003).
- **Flags**: Developer ID: `--options runtime --timestamp` (FR-005). Self-signed and ad-hoc: `--timestamp=none`, no hardened runtime (not needed without notarization, keeps development builds offline-capable).
- **Entitlements**: none. The app reads credentials by running `/usr/bin/security` as a subprocess and makes outgoing HTTPS calls; neither needs an entitlement under the hardened runtime.
- **Alternatives considered**: `find-identity -v` (hides an untrusted self-signed certificate, would force users to change trust settings first); signing by name (ambiguous with duplicate certificates).

## R4. DMG creation and window layout

- **Decision**: `dmgbuild` 1.6.7, run ephemerally through `uvx --from dmgbuild==1.6.7 dmgbuild -s scripts/release/dmg-settings.py`. It writes the Finder window layout (`.DS_Store`), background, icon positions, Applications link and volume icon directly, without scripting Finder, produces a compressed read-only UDZO image, and picks up `name@2x.png` automatically for HiDPI backgrounds.
- **Rationale**: Works without a logged-in desktop or Automation permission, so it suits FR-018 and later CI. `uvx` follows the project's rule of using `uv` and installs nothing globally.
- **Alternatives considered**: `create-dmg` (drives Finder with AppleScript, needs GUI session and a permission prompt); raw `hdiutil` plus hand-written `.DS_Store` (fragile).

## R5. DMG background images

- **Decision**: Two prepared backgrounds per resolution, generated by a committed Swift script `scripts/release/render-dmg-backgrounds.swift` (AppKit text and arrow drawing) and committed as PNGs in `Resources/dmg/`: `background-notarized.png` / `@2x` (drag hint only) and `background-unnotarized.png` / `@2x` (drag hint plus first-launch steps for macOS 14, macOS 15 and later, and the `xattr` command). Window 660 x 440 points, app icon at (165, 175), Applications at (495, 175), instructions in the lower third.
- **Rationale**: The spec assumes prepared images; a generator script keeps the text editable and reproducible without an image editor. Fonts are the system font, so rendering needs no assets.
- **Alternatives considered**: Rendering at release time (adds a build step to every release for no benefit); hand-made images (text not reviewable in diffs).

## R6. Notarization

- **Decision**: Credentials come from a `notarytool` keychain profile, default `agentmeter-notary`, overridable with `NOTARY_PROFILE` (FR-014a). Presence is detected with `xcrun notarytool history --keychain-profile "$NOTARY_PROFILE"`: exit status 0 means available, the message "No Keychain password item found" means missing, and any other failure stops a release instead of downgrading it. The DMG is signed with Developer ID, submitted with `xcrun notarytool submit --wait --keychain-profile`, then `xcrun stapler staple` and `xcrun stapler validate`. On rejection, `notarytool log <id>` output is saved to `build/release/notary-log.json` and the release stops before publishing.
- **Rationale**: Keychain profiles keep secrets out of the repository and environment; the same profile name works on CI after `notarytool store-credentials`.
- **Untestable now**: no Developer ID exists; the path is covered by stubbed tests only (assumption in the spec).

## R7. Version and build number

- **Decision**: `scripts/release/lib.sh` computes:
  - Release mode: HEAD must be exactly at a tag matching `^v[0-9]+\.[0-9]+\.[0-9]+$` and the tree clean; short version `X.Y.Z`, display `X.Y.Z`.
  - Development mode (any other state): short version is the nearest such tag's `X.Y.Z` (`git describe --tags --abbrev=0 --match 'v[0-9]*.[0-9]*.[0-9]*'`, filtered by the regex) or `0.0.0`; display `X.Y.Z-dev`.
  - Build number: `git rev-list --count HEAD` (FR-007). In a shallow clone the count is wrong, so `version_info` prints a warning and the release preflight stops (CI is out of scope; a later workflow must fetch full history).
  - Several `vX.Y.Z` tags on HEAD: the highest version wins (numeric comparison per component).
  - Values are written into the bundle's copy of `Info.plist` with `/usr/libexec/PlistBuddy`: `CFBundleShortVersionString`, `CFBundleVersion`, and a custom key `AgentMeterVersionDisplay`. The source `Resources/Info.plist` keeps `0.0.0` placeholders.
- **App side**: a small `AppVersion` helper in the app target reads `AgentMeterVersionDisplay` (fallback `CFBundleShortVersionString`, then "unknown") and `CFBundleVersion`. It replaces the hard-coded `UsageCore.version` in the launch log line and is shown at the bottom of the Settings window's General tab as "AgentMeter 0.2.0-dev (build 120)" (FR-008's "app's own version display"). `UsageCore.version` and its smoke test are removed.
- **Alternatives considered**: putting "-dev" into `CFBundleShortVersionString` (rejected in spec review, Apple expects numbers only).

## R8. GitHub release flow

- **Decision**: `gh release create vX.Y.Z --draft --verify-tag --title "AgentMeter X.Y.Z" --notes-file <notes>` then `gh release upload` of `AgentMeter-X.Y.Z.dmg`, `AgentMeter-X.Y.Z.dmg.sha256` and `release-info.json`, then `gh release edit vX.Y.Z --draft=false` (FR-015). `--verify-tag` plus a preflight comparison of `git ls-remote origin refs/tags/vX.Y.Z refs/tags/vX.Y.Z^{}` (peeled entry for annotated tags, plain entry for lightweight tags) with `git rev-parse HEAD` enforces FR-016. Replacing assets of an existing release (`--replace`) uses `gh release upload --clobber` and leaves the published state unchanged.
- **release-info.json**: `{ "version", "dmg", "sha256", "tier", "notarized" }`. The cask-only command (FR-021a) downloads it with `gh release download vX.Y.Z -p release-info.json`, so caveats can be rendered for an existing release without guessing.

## R9. Homebrew cask

- **Decision**: The cask is rendered from `packaging/homebrew/agentmeter.rb.tmpl` by `lib.sh` (placeholders for version, sha256, caveats block) and written to `Casks/agentmeter.rb` in a fresh `git clone --depth 1` of `git@github.com:rhuss/homebrew-tap.git` inside `mktemp -d` (FR-021), committed as `agentmeter X.Y.Z` and pushed to `main`.
- **Cask content**: `url "https://github.com/rhuss/agentmeter/releases/download/v#{version}/AgentMeter-#{version}.dmg"`, `name "AgentMeter"`, `desc`, `homepage`, `depends_on arch: :arm64`, `depends_on macos: :sonoma`, `app "AgentMeter.app"`, `uninstall quit: "dev.rhuss.agentmeter"` (FR-024), `zap trash:` with the three paths (FR-023), and `caveats` with the first-launch step only for non-notarized releases (FR-022), plus, in every release, the note that Homebrew quits the app before an upgrade and opens it again afterwards (`brew upgrade` reopens apps closed by `uninstall quit:`, see FR-024).
- **Third-party tap and Gatekeeper**: Homebrew's tightened Gatekeeper policy targets the official `homebrew/cask` repository; casks in a personal tap still install unsigned or self-signed apps, and Homebrew applies the quarantine attribute, which is exactly what the caveats address. The quickstart verifies this with a real install.
- **Alternatives considered**: keeping a permanent local clone of the tap (state can drift); a `postflight` that removes quarantine (rejected in the brainstorm).

## R10. App icon

- **Decision**: `make app` copies `Resources/icons/macos/AgentMeter.icns` to `Contents/Resources/AgentMeter.icns` and sets `CFBundleIconFile` to `AgentMeter` in the source `Info.plist`. The build fails with "missing app icon: Resources/icons/macos/AgentMeter.icns" when the file is absent (FR-006). The DMG uses the same `.icns` as its volume icon (FR-013).

## R11. Release command interface

- **Decision**: Make targets wrap the scripts: `make app` (dev build with tier selection), `make dmg` (dry run: app plus DMG in `build/release/`, FR-019), `make release` (full release), `make cask VERSION=X.Y.Z` (cask-only, FR-021a). Options via environment/make variables: `SIGN_IDENTITY`, `SIGN_IDENTITY_NAME`, `NOTARY_PROFILE`, `ALLOW_ADHOC=1`, `REPLACE=1`. No prompts anywhere (FR-018); every failure exits non-zero with a one-line reason.
