# Tasks: Budget Groups Without an Amount

**Input**: Design documents from `specs/044-no-limit-groups/`
**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/config.md, contracts/ui-strings.md, quickstart.md

**Tests**: Required. Constitution II: logic in UsageCore or DemoMode, test first. Every UsageCore task starts with failing tests in the named test file (a test that does not compile because a type or member is missing counts as failing), then the implementation. Build and test only with `make test`, `make test-release`, `make app`, `make app-demo` (never `swift build`, `swift test` or `xcodebuild` directly).

**Conventions**: Doc comments cite `spec 044 FR-0xx` or research `Rn`; update spec 003, 004 and 043 citations whose rule this spec changes. Exact strings from contracts/ui-strings.md and contracts/config.md. No em or en dashes (the typographic minus U+2212 is allowed). Invented examples in tests, demo and docs (`gateway-a/`, `gateway-b/open-model-12b`, `proj-alpha`, `~/.claude-open`, `~/.codex-open`); real Claude model ids from `Sources/UsageCore/Resources/prices.json` (for example `claude-opus-5-5`: input 4.00, output 20.00, cache write 5m 5.00, 1h 8.00, cache read 0.20 per MTok) are fine.

**Internal model** (research R1): `BudgetGroup` stores an optional amount; `BudgetGroup.budget` returns `BudgetSettings?` (nil without an amount). A group without an amount is never a budget owner, so `budgetOwners`, `budgetOwner(forAccount:)`, `GroupEntry`, `snapshot.groups`, `ThresholdTracker`, pace and burn rate never see it. Do not make `BudgetSettings.budgetUSD` or `BudgetOwner.budget` optional. Reuse spec 043's `NoLimitEntry`, `NoLimitPresentation`, `HeadlineText`, `ReferenceValue`, `DropdownShow` and `OwnBudgetForm` strings; never copy their rules (FR-015).
